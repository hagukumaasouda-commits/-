# プリカ入出金の取消(論理削除) 仕様書 v2

## 背景

プリカ台帳の入力ミスを、これまで「訂正(ADJUST)」種別で±を相殺する記帳で直すしかなかったが、一覧に元の誤った記録と訂正記録の両方が並び、わかりにくいという指摘があった。かといって誤操作防止のため、物理削除で記録そのものを消したくない。

## 設計

`PrepaidTransaction`に取消用のフィールドを追加した(物理削除はしない論理削除)。

- `voidedAt`: 取消日時(nullなら未取消)
- `voidedByStaffId` / `voidedBy`: 取消したスタッフ
- `voidReason`: 取消理由(任意入力)

`app/actions/prepaid.ts`の`voidPrepaidTransaction`で取消を行う。二重送信対策として、既に`voidedAt`が入っている場合は何もしない。

## 残高・集計への反映

残高集計(`_sum.amount`)・プリカ残高消化ペース検出(`lib/reports.ts`)・AI気づきへの残高情報(`lib/awareness/ai-insight.ts`)は、いずれも`voidedAt: null`を条件に加え、取消済みの行を合計から除外する。

全期間明細(`/clients/[id]/prepaid-statement`)は、取消済みの行も時系列の位置にそのまま表示する(取り消し線・グレー表示・「取消済み(日時・担当・理由)」を注記欄に表示)が、残高(期首・期末・各行の残高)・入金合計・使用合計の計算からは除外する(取消済み行の残高欄は「—」表示)。

## UI

顧客詳細ページのプリカ取引一覧・全期間明細のいずれも、取消済みの行は取り消し線付きのグレー表示にして「取消済み」である旨と取消理由・担当・日時を表示する。未取消の行には「取消」の折りたたみを設け、開くと取消理由(任意)の入力欄と確認ダイアログ付きの確定ボタンが現れる。

「訂正(ADJUST)」種別自体は、誤入力の修正以外にも使われうるため残している。誤入力の取り消しには今回追加した「取消」ボタンを使う運用とする。
