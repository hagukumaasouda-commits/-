# 離脱日の入力・メニュー個人データ・物療新規登録 仕様書 v2

## 1. 離脱日の入力・修正

これまで離脱記録の確認日(`DepartureRecord.confirmedAt`、離脱月次集計・フォロー予定の起点日)は常に記録時の現在日時固定だった。過去データの入力時や記録ミス時に実際の離脱日と異なる月にカウントされてしまう問題があったため、以下を変更した。

- 「離脱を記録する」フォームに「離脱日」欄(日付入力、初期値は今日)を追加。過去の日付を指定して記録できる
- 「理由を修正する」フォームにも「離脱日」欄を追加。確認日を修正すると、5件のフォローアップチェックポイント(WEEK3/WEEK6/MONTH3/MONTH6/YEAR1)の予定日も新しい離脱日を起点に再計算する(すでに対応済み(CONTACTED)のチェックポイントも予定日自体は再計算するが、対応記録(連絡方法・反応・対応日時)はそのまま残る)

離脱の月次集計(`getAllChurnEvents`)は`DepartureRecord.confirmedAt`をそのまま離脱日として使っているため、上記の修正だけで当月への誤カウント問題が解消する。

## 2. メニュー(プラン)の個人データ

物療チェックのスタッフ別実施件数(`/treatment-modalities`)と対になる集計として、本日のメニュー(ベーシックケア・リペアネスプラン等)の集計ページ`/menu-plans`(「メニュー集計」)を新設した。期間内の項目別件数・スタッフ別件数を表示する。集計ロジックは`lib/menu-plan-reports.ts`(`getMonthlyMenuPlanCounts`・`getStaffMenuPlanCounts`)。

## 3. 物療の新規登録・新規件数の集計

カルテ入力の物療チェック欄に、項目ごとに「新規」チェックボックス(その項目を今回初めて実施した場合にチェック)を追加した。メインのチェックが外れている項目の「新規」は無効化され、意味を持たない(保存時もサーバー側でメインチェックが無い項目の新規フラグは無視する)。

データは`ChartRecord.treatmentModalitiesNew`(Json、`treatmentModalities`と対の構造)に保存する。`/treatment-modalities`の項目別実施件数テーブルに「新規」列を追加し、新規件数合計のサマリーも表示する。
