# 物販の編集・削除/在庫管理/カテゴリ別集計 仕様書 v2

チャットでの依頼(①物販入力の編集・削除、②仕入れ入力・現在庫の可視化・編集削除、③カテゴリ分けとスタッフ別カテゴリ別集計)をまとめて実装した。v1文書は無く、既存実装調査→実装、という流れで進めた。

## 1. ①物販購入記録の編集・削除

`app/clients/[id]/page.tsx`の「購入履歴(物販)」テーブルの各行を`ProductSaleRow`(クライアントコンポーネント)化し、行内で「編集」ボタンを押すとインライン編集フォーム(新規記録フォームと同じ項目)に切り替わるようにした。「削除」は確認ダイアログ付き。

- `app/actions/products.ts`に`updateProductSale`・`deleteProductSale`を追加。項目パース処理は`recordProductSale`と共通化(`parseProductSaleFields`)。
- CSV取り込み分・手入力分を区別せず、どちらも同じUIで編集・削除できる(依頼に区別の指定が無かったため)。

## 2. ②在庫管理(仕入れ入力・現在庫)

新規モデル`ProductStockIn`(仕入れ記録: 商品・数量・仕入れ日・担当・メモ)を追加。既存の`ProductPurchaseType`(顧客の新規/リピート購入区分)と概念が異なり紛らわしいため、モデル名は「仕入れ」を意味する`ProductStockIn`とし、`ProductSale`(顧客への販売)とは明確に分離した。

新規ページ `/products/inventory`:
- 現在の在庫一覧(商品・カテゴリ・仕入れ累計・販売累計・現在庫)
- 仕入れを記録するフォーム
- 仕入れ履歴一覧(行ごとに編集・削除。物販購入記録と同じインライン編集パターン)

**[確定] 現在庫の計算式**: `現在庫 = 仕入れ数量(ProductStockIn)の合計 - 販売数量(ProductSale.quantity)の合計`。プレゼント品も物理的な在庫は減るため、`isGift`に関わらず全ての販売行を差し引き対象にした。

**[既知の制約]** `ProductSale.quantity`は手入力運用のみで、CSV取り込み分の一部には記録されていない(既存のコメント参照)。個数が未記録の販売は在庫計算から除外される(0扱い)ため、その分だけ現在庫が実際より多く表示される。在庫管理ページの説明文に明記した。

## 3. ③カテゴリ分け・スタッフ別カテゴリ別集計

**[確定] `Product.category`を自由記述からenumに変更**: `ProductCategory { RIPPLE, GRANT, OTHER }`(りっぷる商品/グラント商品/他)。歩合率がカテゴリごとに異なるため、表記ゆれで集計が壊れないよう固定選択肢にした。

**[注意・要確認]** マイグレーションはカラムを一度DROPしてから作り直す形になるため、本番環境で既に`category`に何らかの自由記述が入っていた場合、その値は保持されず全商品が既定値「他」にリセットされる。ローカル確認時点・このリポジトリのシード/既存コードでは`category`を書き込む処理が無かったため実質未使用だったが、本番の`/products/manage`画面から手動で入力されていた場合は反映されない。デプロイ後、`/products/manage`で各商品のカテゴリを再設定する必要がある。

- `lib/tags.ts`に`PRODUCT_CATEGORY_OPTIONS`/`PRODUCT_CATEGORY_LABEL`を追加(単一の情報源)。
- `/products/manage`: カテゴリ欄を自由入力から必須の`<select>`に変更。
- `/products`(物販売上ダッシュボード): 商品別売上テーブルにカテゴリ列を追加。新規セクション「スタッフ別・カテゴリ別売上」で、スタッフごとにカテゴリ別(りっぷる商品/グラント商品/他)の件数・金額と合計を表示(`getStaffProductSalesByCategory`)。プレゼント品は除外(既存のスタッフ別集計と同じ方針)。
