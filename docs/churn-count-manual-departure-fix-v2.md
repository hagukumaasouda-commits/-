# 離脱数カウントの修正・LINE紐づけ解除機能 仕様書 v2

## 背景(ユーザー報告)

「9月に離脱ボタン(離脱を記録する)を押した人が、数値集計ダッシュボードの離脱数に反映されていないようだ」という報告。

## 原因

ダッシュボードの「離脱数」「離脱率」「スタッフ別離脱率」は、すべて`lib/reports.ts`の`getChurnedClientIds()`を参照している。このロジックは**完全に自動計算**で、「最終来院日から必要来院ペース×3(未設定なら6週間)以上経過し、かつ未来の予約が無い」顧客だけを離脱扱いにしていた。

一方、顧客詳細ページ・顧客一覧の「離脱」バッジや、離脱フォローアップ機能は`Client.isActive`(スタッフが「離脱を記録する」ボタンを押すと`confirmDeparture`アクションでfalseになる)を参照している。

つまり**2つの異なる「離脱」の定義が併存**しており、スタッフが手動で離脱を記録しても、自動計算側の閾値にまだ達していなければダッシュボードの離脱数には一切反映されなかった。

## 修正方針

`getChurnedClientIds()`を、以下のいずれかを満たす顧客の集合(未来の予約がある場合は除く)に変更する:
- (A) 従来通りの自動判定(最終来院からの経過日数)
- (B) `DepartureRecord`により手動確認済み、かつまだ復帰(来院)していない顧客 ← 新規追加

(B)の判定は`Client.isActive`の現在値ではなく、`DepartureRecord.confirmedAt`と「その後の来院有無」から都度計算する。`isActive`は現在値のみを保持し来歴を持たないため、ダッシュボードで過去の期間(先月など)を表示した際にも正確な値になるようにするため。

この修正により、`getChurnedClientIds()`を参照する離脱率・スタッフ別離脱率・プリカ残高消化ペース検出にも同様に反映される。離脱候補一覧(`lib/departures.ts`の`getPaceBasedCandidates`)は`isActive: true`のみを対象とする既存ロジックのままのため、手動確認済みの顧客が「要確認」候補として再度表示されることはない。

## LINE紐づけ解除機能

`/line-friends`のリンク済み一覧の各行に「紐づけ解除」ボタンを追加した(顧客情報自体は削除しない、リンクのみを解除する)。誤って別の顧客にリンクしてしまった場合の訂正用。解除すると`LineFriend.linkedClientId`等がnullに戻り、`Client.lineUserId`もnullに戻る(再度別の顧客にリンクし直せる)。
