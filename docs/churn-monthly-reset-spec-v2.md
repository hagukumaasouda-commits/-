# 離脱数の月次リセット 仕様書 v2

## 背景(ユーザー報告)

「離脱の情報が9月のが引き継がれているので、月ごとにリセットしてその月の離脱がわかるようにしたい」

## 原因

ダッシュボードの「離脱数」「離脱率」「スタッフ別離脱率」「離脱一覧」は、`getChurnedClientIds()`(docs/churn-count-manual-departure-fix-v2.md で手動確認も含めるよう拡張済み)の**その時点でのスナップショット**(「期間終了時点で、まだ離脱状態が解消されていない人」)を参照していた。このため、9月に離脱と判定された人は、10月になっても来院して復帰しない限り、10月のダッシュボードにも同じ人数としてそのまま出続けていた(スナップショットである以上、これ自体は意図通りの動作だったが、「月ごとの集計」としては不便だった)。

## 修正方針

ダッシュボードの離脱系指標(離脱数・離脱率・スタッフ別離脱率・離脱一覧)を、**「離脱と判定された日」を基準にその月に属するものだけを数える**方式に変更する(新規来院数・再診数と同じ「期間内に発生した件数」の考え方に揃える)。

### 離脱と判定された日の算出

- **自動判定**: 来院の間隔を顧客ごとに時系列で見て、「前回来院日から必要来院ペース×3(未記録なら6週間)」を超えた箇所をすべて検出する(現在進行中の間隔だけでなく、過去に発生して既に次の来院で解消された間隔も含む)。離脱と判定された日 = 前回来院日 + しきい値日数
- **手動判定**: `DepartureRecord.confirmedAt`をそのまま採用する
- 同一の間隔に対して自動判定と手動判定の両方が当てはまる場合(しきい値を超えた後にスタッフが離脱ボタンを押した場合)は、手動判定(具体的な確定日がある方)を優先し、自動判定側は出さない(二重カウント防止)
- 現在進行中(まだ次の来院が無い)間隔のみ、未来の予約がある場合は対象から除外する(既存の`getChurnedClientIds`と同じ条件)

### 既存の「現在離脱中かどうか」を見る機能は変更しない

以下は「今まさに対応が必要な人」を知るための運用機能であり、月次集計とは目的が異なるため、スナップショット方式(`getChurnedClientIds`)のまま変更しない:
- 離脱フォローアップの候補一覧(`lib/departures.ts`)
- プリカ残高消化ペース検出(ダッシュボードの「プリカ残高消化ペースの気づき」)

### 離脱率の分母

分子(その月に新たに離脱と判定された人数)は変更するが、分母(`totalClients`、期間終了時点で登録済みの全顧客数)は変更しない。離脱は「来なくなった人」の集計のため、新規来院数等と同じ「その月に来院した人」を分母にすると定義上ほぼ数字が出ない(離脱した人は基本その月に来院していない)。
