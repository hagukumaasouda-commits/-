# 気づきチェック:事務チェック対象フィールド拡張・AI気づき土台修正 仕様書 v2

2つのアップロード文書(「気づきチェック:事務チェック(記入漏れ)対象フィールド拡張 仕様書 v1」「AI気づきチェック:土台修正 仕様書 v1」)を実装のためレビューし、既存コードとのフィールド名の不一致を補正した上で実装した。

## 1. 事務チェック(`lib/awareness/office.ts`)対象フィールド拡張

v1のまま実装。死んでいた`ChartRecord.requiredFields`によるチェックを削除し、他に使用箇所が無いことを確認した上でスキーマからも削除した(マイグレーションで`DROP COLUMN`)。`prisma/seed.ts`のサンプルデータからも該当行を削除。

最終的な対象フィールド(11項目、既存6項目+新規5項目)は v1の表の通り実装した。

**[v2で補正] #11(必要来院ペース)のフィールド所在**: v1は「`Client.requiredVisitInterval`」としていたが、このフィールドは`Client`ではなく`ChartRecord`(来院ごと)に存在する(`docs/departure-followup-spec-v2.md`で定義済み)。既存の離脱判定ロジック(`lib/reports.ts`)も同様に「直近の来院に紐づくChartRecordの値」を参照している。本実装ではこの実際の所在(`chart.requiredVisitInterval`、今回のカルテ自身の値)を判定対象とした。

**[v2で追加修正] #2(本日のメニュー)・#9(生活習慣サポート)が実際には発火しなかった問題**: 実装後のブラウザ確認で、この2項目が常に「入力済み」判定になり、意図した記入漏れ検知が機能しないことが判明したため、以下の通り原因を修正した。

- `Visit.menu`は、既存のメニュー自動生成コンポーネント(`VisitMenuBuilder`、`docs/client-list-timeline-menu-spec-v2.md`)が、プラン・タグ・物療のいずれも未選択でも`"()+"`という空でない文字列を生成して送信していたため、`!visit.menu`が常にfalseになっていた。`VisitMenuBuilder`側を修正し、何も選択されていない場合は自動生成テキストを空文字列にした(#2のチェックはコード変更不要で正しく動くようになった)
- `ChartRecord.lifestyleSupportStatus`は、来院記録フォームの`createVisit`アクションが常に全20項目分の`{項目名: true/false}`オブジェクトを送信するため(未チェックはfalseとして送信)、値が`null`になることは無い。「未入力」の実態は「全項目がfalse(実施項目が一つもない)」であるため、#9の判定条件を`lifestyleSupportStatus == null`から「全項目の値がfalse」に修正した

**#8(ランク)の実装範囲**: v1の補足に従い、「未入力かどうか」のみの段階的実装とした(「前回来院時から更新されていない」の判定は見送り)。理由: `Client.rank`は現状値のみを保持する単一フィールドで、来院ごとの履歴を持たないため、「前回来院時点の値」と比較する仕組みが存在しない。将来的に必要になった場合は、来院ごとにランクの履歴を残す設計变更が別途必要になる。

## 2. AI気づき(`lib/awareness/ai-insight.ts`)土台修正

v1のまま実装。

### 2.1 離脱判定閾値の統一

固定値`CHURN_THRESHOLD_DAYS`(42日)を渡すのをやめ、`docs/departure-followup-spec-v2.md`2.2節と同じ「直近の来院の`requiredVisitInterval`を日数換算 × 3」を計算して渡すようにした。日数換算テーブル(`VISIT_INTERVAL_DAYS`)と倍率(`CHURN_INTERVAL_MULTIPLIER`)は`lib/reports.ts`の既存の値をexportして再利用し(二重管理を避けるため)、`requiredVisitInterval`が未記録の場合のみ42日にフォールバックする。

### 2.2 AIへ渡すデータの拡充

v1の表の通り、ランク・必要来院ペース(直近値)・回復度(直近値)・既往/家族データ/個人データ・離脱記録履歴・担当変更相談履歴・生活習慣サポート実施状況(直近値)を`buildClientContext`に追加した。

**[v2で確定] 履歴データの要約方式**: 離脱記録・担当変更相談の履歴は、2.3節の許容に従い「件数 + 直近1件の要約」の形で渡す(全件の詳細は渡さない)。

### 2.3 エラー時のUI表示

**[v2で具体化]** `saveAiInsights`/`generateAiInsights`の戻り値を`{status: "ok"|"error"|"not_configured", insights: [...]}`型に変更した。

UI側は、既存の「気づきチェックする」ボタンを`useActionState`を使うクライアントコンポーネント(`app/clients/[id]/awareness-check-button.tsx`)に切り出し、サーバーアクション`runAwarenessCheck`の戻り値(直近の実行結果)をボタン直下に表示する形にした。

**[v2で確定] 表示位置の簡略化**: v1は「AI気づき」セクション(`AwarenessLane`、`checks.length === 0`のときの「まだありません」表示)側での出し分けを想定していたが、`AwarenessLane`は保存済みの`AwarenessCheck`をDBから読む純粋な表示コンポーネントで、「直前の実行が失敗したかどうか」という一時的な状態を持たない。今回はボタン直下(気づきチェックセクション内、AI気づきレーンのすぐ上)に、直前の実行結果としてエラー/未設定メッセージを表示する形にした。ページを再読み込みすると消える一時的な表示である(DBに永続化はしない)。事務チェック側の表示・挙動は変更していない。
