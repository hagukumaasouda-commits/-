# 数値集計ダッシュボード スタッフ別内訳・詳細リスト 仕様書 v2

ユーザー依頼(5点)への対応方針をまとめる。

## ①② 個人(スタッフ)別の数値

ダッシュボード・物療集計に記載されている指標について、スタッフ別の内訳を追加する。各指標のスタッフへの帰属(アトリビューション)ルールは以下の通り(既存のスタッフ別離脱率・6回以上リピート率等と揃える):

| 指標 | 帰属先 | 備考 |
|---|---|---|
| 新規来院数 | 新規顧客の`primaryStaffId`(主担当) | |
| 離脱数 | 離脱顧客の`primaryStaffId` | 既存の`staffChurnRate`の`churnedClients`をそのまま利用 |
| 再診数(離脱後の復帰) | その来院(Visit)の`staffId`(実際に施術した人) | 復帰した日に誰が診たかが重要なため主担当ではなく施術担当 |
| 15回以上リピーター | 顧客の`primaryStaffId` | ④参照。母数は`getStaffCaseload`と同じ「期間終了時点で登録済みの担当顧客」 |
| 初回→2回目移行率 | 新規顧客の`primaryStaffId` | |
| 紹介率 | 新規顧客の`primaryStaffId` | |
| 平均通院回数・平均通院期間 | 顧客の`primaryStaffId` | |
| カルテ枚数(⑤) | その来院(Visit)の`staffId` | 実際に記録した人の実績として集計 |

担当者未設定(`primaryStaffId`がnull)の顧客・データは、スタッフ別集計からは除外する(既存のスタッフ別集計と同じ扱い)。

ダッシュボードの表示は、指標の性質で3つの表に分ける(1つの表に9列以上詰め込むと見づらいため):
1. **スタッフ別 主要指標(率)**: 担当数・リピート率(2回以上)・6回以上リピート率・離脱率・初回→2回目移行率・紹介率(既存の表に2列追加)
2. **スタッフ別 件数集計**: 新規・再診数・離脱数・15回以上リピーター・カルテ枚数(新設)
3. **スタッフ別 平均通院**: 平均通院回数・平均通院期間(新設)

物療集計(`/treatment-modalities`)には、項目別実施件数の表とは別に「スタッフ別実施件数」の表(行=スタッフ、列=物療項目+合計)を追加する。

## ③ 新規・再診・離脱数のリスト表示

該当する3つのStatCardを、クリックで展開する`<details>`ベースのカード(`ListStatCard`)に変更する(新しいページ遷移やJSは使わず、既存の折りたたみパターンを踏襲)。表示内容:
- 新規: 顧客名(リンク)・初回来院日・担当スタッフ
- 再診: 顧客名(リンク)・来院日・施術担当スタッフ
- 離脱: 顧客名(リンク)・最終来院日・主担当スタッフ

## ④ 15回以上リピーターのカウント方法

現状の実装(`countRepeatersAtLeast`)は、期間終了時点(`asOfNow(period)`)を基準に「その時点までの通算来院回数」で判定しており、既に期間内来院者に限定しない全顧客ベースの累計カウントである。ただし、ダッシュボードの期間ナビゲーション(週次/月次・前後移動)に連動して基準日が変わるため、過去の期間を表示すると当然その時点の数字になり、「今月分だけの数字」であるかのように見える。

これは既存の`getBirthdayClientsThisMonth`(誕生日アラート)と同じ問題であり、同じ解決方針を採る: **15回以上リピーターの人数(全体・スタッフ別とも)は、ダッシュボードの期間選択から独立させ、常に「現在時点(today)」での累計来院回数で判定する**。期間を前後に移動しても数字が変わらない、常に最新の「現在のロイヤル顧客数」を示す指標にする。

## ⑤ カルテ枚数

期間内に作成されたChartRecordの件数(来院記録に紐づく分)を、全体・スタッフ別(実際に施術したスタッフ)で集計する。1来院=1カルテのため、実質「期間内の総来院件数」と同義になる。
