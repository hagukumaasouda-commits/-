# カルテ改修・プリカ/物販機能 仕様書 v2

はぐくまCRMの来院記録フォーム・顧客詳細ページに対する改修仕様。v1(アップロードされたMarkdown、リポジトリ外)からの変更点は **[v2で変更]** として明示する。

## 1. 主訴タグ・施術部位タグの拡張

v1のまま。`lib/tags.ts`の`CHIEF_COMPLAINT_TAGS`(10→17件)・`BODY_PART_TAGS`(10→12件)を拡張する。

## 2. 関わりの記入欄の追加

### 2.1 来院記録フォームへの追加(`ChartRecord`、毎回更新)

**生活習慣サポート実施状況**(チェックボックス、20項目)

てる1 / てる2 / てる3 / 水 / 呼吸 / 食分析 / 酵素 / OK・NG / コアレ / ブースタ / セラゼム / ニュースキャン / 陰陽食 / 靴・靴ひも / 睡眠 / 姿勢 / 立ち方 / 座位 / デスク / Bトレ

**[v2で確定] 表記**: 略称(てる1、コアレ等)のまま表示する。正式名称への展開は行わない。

フィールド: `ChartRecord.lifestyleSupportStatus`(Json、`{ "てる1": true, ... }`形式で項目名をキーにした真偽値マップ)。

**健康実践状況**

**[v2で変更] タグ選択は廃止し、自由記述のみとする。** 来院ごとに`ChartRecord`に記録されるため、来院タイムライン上に自然に時系列で蓄積・一覧表示される(過去の記録を上書きしない)。

フィールド: `ChartRecord.healthPracticeNote`(String、任意)。来院タイムラインの表示にも追加する。

### 2.2 顧客の基本情報への追加(`Client`、初回記入・以後編集可)

- `Client.medicalHistory`(String、任意)既往
- `Client.familyData`(String、任意)家族データ

**[v2で確定] 顧客編集ページの新設**: 現状「顧客詳細」に編集機能が無く(新規登録のみ)、電話番号・住所なども後から直せない。既往・家族データだけでなく、`Client`の主要フィールド(氏名・カナ・性別・電話・郵便番号・住所・職業・来店きっかけ・紹介元・主担当・初回来院日)をまとめて編集できる`/clients/[id]/edit`ページを新設する。

## 3. 料金・会計まわり(全面的に手入力方式で統一)

方針は v1のまま: 自動計算ロジックは組み込まず、金額はすべて手入力。システムは合計・残高の集計のみ自動で行う。

### 3.1 プリカ台帳

**[v2で確定] 新規テーブルは作らず、既存の`PrepaidTransaction`モデルを拡張する。** 既存モデルは`txType`(CHARGE/USE/ADJUST)・`amount`・`balanceAfter`・`txDate`・`visitId`(任意)・`note`を持つ。v1が求める`type`(入金/使用)・`amount`・`date`・`staff_id`・`note`とほぼ1対1で対応するため、不足している`staffId`のみ追加する。

| 変更 | 内容 |
|---|---|
| `PrepaidTransaction.staffId` | 追加(参照、任意)。記録した担当スタッフ |

- `type`は既存の`txType`(CHARGE/USE)をそのまま使う。既存の`ADJUST`(訂正)も、手入力運用では誤入力の訂正に使えるため選択肢として残す(v1にはないが、UIのラベルは「入金/使用/訂正」の3択とする)
- 金額の符号は既存の慣習を踏襲: 画面上はどちらも正の数値を入力してもらい、`USE`选択時はサーバー側で符号を反転してマイナスとして保存する(スタッフに負の数を入力させない)
- プリカ残高 = 入金の合計 − 使用の合計(既存の集計ロジックのまま、変更不要)
- 画面表示用の早見表(ポイント付与の目安)は静的なUI表示のみ。データモデル化・計算連動はしない

### 3.2 施術メニュー表

v1のまま。静的な参考価格表をUIに表示するのみ。データモデル変更なし。

### 3.3 物販購入記録

**[v2で確定] 新規テーブルは作らず、既存の`ProductSale`モデルを拡張する。** 既存モデルは`productId`・`clientId`・`staffId`・`saleDate`・`amount`・`itemType`・`purchaseType`・`isGift`・`dedupKey`(CSV取り込み用の一意キー、必須)を持つ。手入力用に以下を変更する:

| 変更 | 内容 |
|---|---|
| `ProductSale.quantity` | 追加(Int、任意)。個数 |
| 手入力時の`dedupKey` | CSV取り込み(日付+顧客+商品+担当から生成)とは別に、手入力時はランダムなキーを生成して一意制約を満たす(サロンボードCSVの再取り込み防止ロジックとは独立) |
| `itemType` / `purchaseType` | 手入力フォームでは`FULL`(本品)/`NEW`(新規)を既定値にし、必要に応じて変更できるようにする |

**[v2で確定] 商品マスタ(`Product`)の投入方法**: 現状`Product`テーブルは0件(CSV取り込みも無いため実質未使用)。ユーザーから実際の商品名リストを受け取り次第、`prisma/seed-production.ts`と同様のupsert方式で本番マスタとして投入する。
